# vacation_picker

Personal web app to pick a vacation destination: browse proposals as
cards, open one for details (description, budget, transport, hashtags).

## Stack

- **Backend** (`backend/`): NestJS + TypeScript, raw SQL via `pg` (no
  ORM, deliberate, for SQL practice). One module per resource
  (`destination/`, ...), each importing `DatabaseModule` for the shared
  `DatabaseService` pool.
- **Frontend** (`frontend/`): React 19 + TypeScript + Vite, `react-router`.
- **Database**: PostgreSQL. Schema in `db/init/*.sql`, applied on first
  boot of an empty volume.
- **Infra**: `docker-compose.yml` runs db + backend + frontend; `make up`.

## Conventions

Project-agnostic engineering standards live in `~/42/WIP/CLAUDE.md`. The
local summary and the exact commands are in `CONTRIBUTING.md`. In short:

- one branch = one PR, rebased on `main`, `/code-review` before merge
- Conventional Commits, atomic, English only
- CI (`.github/workflows/`) must be green: format / lint / typecheck /
  test / build for both packages, plus gitleaks
- secrets in `.env` only (git-ignored), `.env.example` kept current
- raw SQL: parameterised queries only; build dynamic clauses from a
  hardcoded column whitelist, never from client keys (see
  `destination.service.ts` `update`)
- structural decisions get an ADR in `docs/adr/`

## Notes

- No ORM is a deliberate constraint, not an oversight - don't propose
  adding one.
- `api-docs/` is generated by `npm --prefix backend run doc` (Compodoc)
  and git-ignored - don't commit it.
